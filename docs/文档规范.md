# Wanna Understanding — 文档规范

> 本文档定义项目文档的编写规范、模板和最佳实践。

---

## 1. 文档目录结构

```
docs/                     # 文档根目录
  adr/                    # 架构决策记录（Architecture Decision Records）
    0001-xxx.md           # ADR 编号 + 标题
  plans/                  # 计划文件
    当前任务计划.md        # 当前任务计划（临时）
  README.md               # 文档目录说明

项目根目录：
  README.md               # 项目介绍（首页）
  ARCHITECTURE.md         # 架构概述
  CONTEXT.md              # 领域术语表
  CONTRIBUTING.md         # 贡献指南
  CLAUDE.md               # AI Agent 规则
  LICENSE                 # 许可证
  .gitignore              # Git 忽略规则
```

## 3. 编写规范

### 3.1 Markdown 格式

- 所有文档使用 **UTF-8** 编码（无 BOM）
- 换行符：**LF**（`\n`）
- 文件扩展名：`.md`
- 标题层级：`#` → `##` → `###` → `####`（跳级不允许）

### 3.2 语言

- **默认中文**（项目主要语言为中文）
- 如需双语，创建 `_zh.md`（中文）和 `.md`（英文）两个版本
- 术语首字母大写，与 `CONTEXT.md` 保持一致

### 3.3 引用格式

- 文件引用：`[文件名](路径/文件.md)`
- 代码引用：行内 `` `code` `` 或代码块 ` ``` `
- ADR 引用：`[ADR-0001](docs/adr/0001-xxx.md)`

### 3.4 表格格式

```
| 列 1 | 列 2 | 列 3 |
|------|------|------|
| 内容 | 内容 | 内容 |
```

- 表头与内容对齐
- 状态列使用统一符号：✅ 已完成，⬜ 未开始，🟡 进行中，🟢 已计划

### 3.5 代码块

- 标注语言：```python, ```bash, ```powershell, ```json
- 命令示例要有明确的说明文字

## 4. 架构决策记录（ADR）

### 4.1 何时写 ADR

以下场景必须写 ADR：
- 引入新的技术栈或框架
- 修改目录结构或包组织方式
- 设计核心数据模型或 API 协议
- 重要的架构重构

### 4.2 ADR 模板

```markdown
# ADR-000N：标题

- **状态**：[草案 | 已接受 | 已废弃 | 已替代]
- **提出日期**：YYYY-MM-DD
- **最后更新**：YYYY-MM-DD

---

## 上下文

[描述问题背景、驱动因素]

## 决策

[描述做出的决策]

## 理由

[为什么选这个方案，放弃哪些方案]

## 影响

[正面和负面的后果]

## 相关 ADR

- [ADR-000X](000X-xxx.md)
```

### 4.3 ADR 编号规则

- 从 `0001` 开始递增
- 文件名格式：`{编号}-{英文kebab-case标题}.md`
- 状态变化时更新文件头

---

## 5. 文档维护

### 5.1 更新触发条件

以下情况须同步更新文档：
- 新增/修改 API 接口
- 修改目录结构
- 修改构建或部署流程
- 修改核心数据模型
- 修复记录在 `docs/错误集.md` 中的 Bug

### 5.2 文档 review

- PR 中的文档变更需要和代码变更一起 review
- 文档中的技术信息必须与代码一致
