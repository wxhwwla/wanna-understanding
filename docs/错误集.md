## 当前错误

### [ERR-001] venv 内 pip 因编码损坏无法使用

- **发现日期**：2026-06-17
- **严重程度**：SEV-MED
- **模块**：环境 / 工具链
- **状态**：已修复（提供重建脚本）

#### 现象

执行 `.venv\Scripts\pip.exe` 报 `SyntaxError: unterminated string literal`，堆栈指向 `pip\_vendor\rich\_emoji_codes.py`。

#### 原因

虚拟环境在非 UTF-8 环境下创建或更新，导致 site-packages 内文本文件损坏。

#### 修复方案

1. 双击运行仓库根目录 `修复venv.bat` 重建 venv；
2. 创建前设置 `$env:PYTHONUTF8 = "1"` 与 `chcp 65001`；
3. 若 pip 仍不可用，可用系统 Python：`pip install -t .venv\Lib\site-packages -e ".[dev,ocr]"`。

### [ERR-002] 截图区域 DPI 宽高重复缩放

- **发现日期**：2026-06-17
- **严重程度**：SEV-MED
- **模块**：`screen/region.py`
- **状态**：已修复

#### 现象

高 DPI 显示器上截图区域偏移或只截到部分客户区。

#### 原因

`ClientToScreen` 返回的 x/y 已是物理坐标，但对 width/height 再次乘以 `dpi_scale`。

#### 修复方案

`physical_rect()` 仅对 width/height 乘 DPI；x/y 保持原值。见 `WindowRegion.physical_rect()`。

### [ERR-003] VS Code/Cursor 开启 UIA 后仍走 OCR 且效果差

- **发现日期**：2026-06-17
- **严重程度**：SEV-LOW
- **模块**：`screen/text_extract.py`、设置 GUI
- **状态**：已修复（文档与 UI 提示）

#### 现象

`WU_USE_UIA=true` 后识别无改善或仍很慢。

#### 原因

Electron 编辑器控件树通常不暴露完整文档文本，UIA 返回空，自动回退 OCR。

#### 修复方案

对 VS Code/Cursor 保持 `WU_USE_UIA=false`；UIA 更适合传统 Win32 编辑器。设置对话框已增加说明。

- **严重程度**：SEV-LOW

### [ERR-005] 流式 AI 报错 `'str' object has no attribute 'decode'`

- **发现日期**：2026-06-17
- **严重程度**：SEV-MED
- **模块**：`ai/stream.py`
- **状态**：已修复

#### 现象

配置 API Key 后，悬浮窗显示 `分析失败: 'str' object has no attribute 'decode'`。

#### 原因

`httpx>=0.28` 的 `response.iter_lines()` 默认返回 `str`，旧代码按 `bytes` 调用 `.decode()`。

#### 修复方案

`iter_sse_deltas` 同时兼容 `bytes` 与 `str` 行（见 `_line_to_text`）。

### [ERR-007] 蓝角/底边/右边缩放热区无法拖拽

- **发现日期**：2026-06-17
- **严重程度**：SEV-MED
- **模块**：`ui/overlay.py`
- **状态**：已修复

#### 现象

拖拽右下角蓝色方块或底边/右边来缩放悬浮窗无效。

#### 原因

1. 热区太小：蓝角仅 20x20px，底边/右边仅 8px
2. `Text` 控件拖拽事件与缩放热区 Frame 存在事件竞争
3. 无效光标名 `"size_s"` 和 `"size_we"`（X11 名，Windows 不存在）

#### 修复方案

1. 热区增大：蓝角 20→28px，底边/右边 8→12px
2. 移除 `Text` 控件的拖拽绑定（仅标题栏可拖拽移动）
3. 修正光标名为 Windows 原生值

### [ERR-008] Trae 编辑器 OCR 识别率极低

- **发现日期**：2026-06-18
- **严重程度**：SEV-HIGH
- **模块**：`ocr/profiles.py`、`ocr/preprocess.py`、`ocr/engine.py`
- **状态**：已修复

#### 现象

OCR 仅识别出 20-30 个字符（如 `6，55`），反复提示"未识别到有效代码"。

#### 原因

1. Trae 未被 `detect_editor_profile` 识别，回退到 `generic`（放大 2.0x，无固定阈值）
2. 自适应阈值用 50% 分位，代码文字仅占 ~25%，阈值过高
3. 置信度阈值 `min_confidence=0.5` 过高

#### 修复方案

1. 新增 `trae_dark` profile（继承 `vscode_dark`）
2. `detect_editor_profile` 增加 `"trae" in title` 检测
3. 自适应阈值从 50th 改为 25th 百分位，`min_confidence` 从 0.5 降到 0.3

### [ERR-009] 悬浮窗死机：`_tkinter.TclError: bad cursor spec`

- **发现日期**：2026-06-18

- **模块**：`ui/overlay.py`

### [ERR-012] HiDPI 屏幕窗口只占左上角 2/3（DPI 未感知）

- **发现日期**：2026-06-18
- **严重程度**：SEV-HIGH
- **模块**：`tcl_bootstrap.py`、`screen/region_confirm.py`
- **状态**：已修复

#### 现象

全屏窗口只覆盖屏幕左上角约 2/3，其余为黑屏。

#### 原因

Python 默认不是 DPI 感知进程。在 150% DPI 缩放下，`winfo_screenwidth()` 返回物理像素而
`-fullscreen` 创建逻辑尺寸窗口，尺寸不匹配。

#### 修复方案

`tcl_bootstrap.py` 模块级调用 `SetProcessDPIAware()`，任何窗口创建前启用 DPI 感知。

### [ERR-013] OCR 英文代码识别质量差：符号混淆

- **发现日期**：2026-06-19
- **严重程度**：SEV-HIGH
- **模块**：`ocr/engine.py`、`ocr/recognizer.py`、`ocr/preprocess.py`
- **状态**：已修复

#### 现象

OCR 输出严重变形：`from __future__ import` → `from future_- iport`、`sys` → `Sy5`、
`Path(__file__)` → `PathC_file-`。AI 回复"代码严重损坏"。

#### 原因

1. 语言列表含 `ch_sim` 导致英文特殊符号识别率下降
2. 放大不足（generic 2.0x），`_MAX_OCR_EDGE=1600` 限制有效放大
3. 后处理仅 6 条规则，缺少 Python 关键字修复
4. 二值化丢失灰度细节

#### 修复方案

1. 默认语言 `["en"]`（移除 `ch_sim`）
2. generic 2.0→2.5x，`_MAX_OCR_EDGE` 1600→2400
3. 后处理增至 22 条规则
4. 去掉二值化，改用灰度+锐化+对比度增强

### [ERR-014] AI API 频繁 SSL 握手超时 + 心跳消息误导

- **发现日期**：2026-06-19
- **严重程度**：SEV-HIGH
- **模块**：`ai/client.py`、`config.py`、`analysis_coordinator.py`
- **状态**：已修复

#### 现象

分析失败：`_ssl.c:1003: The handshake operation timed out`（60 秒超时）。
同时悬浮窗一直显示"正在识别代码"即使已进入 AI 调用阶段。

#### 原因

1. 默认 `request_timeout=60s` 对某些网络下 SSL 握手不够
2. 心跳函数固定文案，不区分 OCR 和 AI 阶段

#### 修复方案

1. 超时 60s→120s（视觉模式额外 300s）
2. 心跳分阶段：`phase` 可变引用，AI 阶段显示"正在调用 AI 分析"

### [ERR-015] 剪贴板读取：SendInput/keybd_event 对 Electron 编辑器无效

- **发现日期**：2026-06-19
- **严重程度**：SEV-HIGH
- **模块**：`screen/clipboard_reader.py`
- **状态**：已修复

#### 现象

剪贴板模式运行，日志显示清空剪贴板、发送 Ctrl+A/Ctrl+C 均成功，
但剪贴板在按键后无 UNICODETEXT 格式，回退 OCR。

#### 原因

SendInput/keybd_event 的键盘模拟被 Electron 应用（VS Code/Trae/Cursor）忽略。
Electron 使用 Chromium 的输入处理，不走标准 Windows 消息队列。

#### 修复方案

用 PowerShell SendKeys（WScript.Shell COM 对象）替代 SendInput。
COM 走不同的输入注入层，Electron 无法区分真实按键和 COM 模拟按键。

### [ERR-016] 悬浮窗拖拽闪烁 + 松开变小

- **发现日期**：2026-06-19
- **严重程度**：SEV-MED
- **模块**：`ui/overlay.py`
- **状态**：已修复

#### 现象

拖拽悬浮窗时画面闪烁；松开鼠标后窗口尺寸跳回最小尺寸（280x180）。

#### 原因

Tkinter 的 winfo_width()/winfo_height() 返回异步缓存值。几何设置通过 Tkinter
事件队列异步生效，导致回调间反复横跳。释放时读到未更新缓存值覆盖宽高。

#### 修复方案

1. 不依赖 Tkinter 缓存：_on_drag 直接用 self.width/height。
2. 缩放中同步：_on_resize 每步更新 self.width/height。
