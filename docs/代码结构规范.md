# 代码结构规范

> **受众**：维护者、贡献者、AI Agent（新代码与重构均须遵守）

---

## 1. 两条铁律

### 1.1 目录宽度

- 任意目录下 **直接子项（文件 + 文件夹）≤ 20（硬顶）**；**目标 ≤ 15**（超过 15 时应规划拆分子目录）。
- **数子项时包括**：`.py`、子文件夹、`README.md` 等；**不包括** `__pycache__`、`.pytest_cache`。
- 第 **21** 个子项出现前，必须先建子目录并迁入，或合并相关文件。

### 1.2 文件长度

- **目标**：单个 `.py` **≤ 400 行**（可读、可测、可 review）。
- **硬顶**：业务代码 **> 500 行不得新增**；已有超长文件列入迁移 backlog。
- **例外申请**：须在 PR 或 Issue 说明理由，并更新本文件 §5 豁免表。

---

## 2. 放什么、不放什么

| 位置 | 放 | 不放 |
|------|----|------|
| `src/` | 核心业务逻辑 | GUI、展示层 |
| `scripts/` | CLI 入口脚本、工具 | 包内 import 的模块 |
| `tests/` | 测试代码 | 与生产无关的杂物 |
| `resources/` | 静态资源文件 | 代码模块 |
| `docs/` | 项目文档 | 代码、配置文件 |

---

## 3. 命名与拆分手法

1. **先按领域拆目录**，再按职责拆文件。
2. 单类过大：用 **mixin** 或 **按模块拆文件**。
3. 纯函数集合：独立 `*_helpers.py`，由薄 `__init__.py` 聚合 re-export。
4. 注释语言：**中文**。
5. 导入规范：
   - 包内模块使用相对导入：`from . import xxx`
   - 包内交叉引用用相对导入：`from .xxx import yyy`
   - 入口脚本用绝对导入
   - 包目录必须有 `__init__.py`
6. 导入排序：`future → 标准库 → 第三方 → 本地应用` 四组排序，组间空行，每组内字母序。
7. 每个 `__init__.py` 必须声明 `__all__` 列表。空包写 `__all__: list[str] = []`。
8. 所有 `.py` 文件首行必须有 `# -*- coding: utf-8 -*-`。
9. 文档字符串：Google 风格，中文。

## 6. Agent / PR 自检清单

提交前（或 Agent 完成大块后）：

- [ ] 未新增「目录直接子项 > 20」（目标 ≤ 15）
- [ ] 未新增「业务 .py > 400 行」（硬顶 500）
- [ ] 测试路径与生产结构对齐
- [ ] 较大结构变更已更新 `docs/会话接续手册.md`
- [ ] 导入规范：新增模块使用显式相对/绝对导入；包目录有 `__init__.py`
- [ ] 导入排序：import 按 `future → stdlib → third-party → local` 四组顺序
- [ ] 编码头：新 `.py` 文件首行有 `# -*- coding: utf-8 -*-` 声明
- [ ] `__all__` 声明：新 `__init__.py` 声明了 `__all__` 确定公共 API
- [ ] 文档字符串：公共 API 与长函数（≥40 行）有 Google 风格 docstring
- [ ] 测试命名：测试函数 `test_` 前缀
